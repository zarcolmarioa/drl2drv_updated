WHAT EACH VERSION VARIES
----------------------------------------------------------------------
  Everything except the variant, the colour cut, the bin
  mode and the stream setting is held identical, so a
  difference between two versions is the thing being varied
  and nothing else. Only the control varies the streams.

    current        original levels, no cut   (the baseline)
    extra_levels   vivid levels,    no cut
    larger_diffs   original levels, cut
    both           vivid levels,    cut
    sens_cut_*     the cut varied, vivid levels
    reproduction   a control, not a candidate

0a. STREAM SEPARATION  (the check on the comparison itself)
----------------------------------------------------------------------
  The colour cut filters `sat_only` and nothing else, so two
  versions built from the same ladder should have the SAME
  fog_only, together and conflict trials.

  Off a single random stream they did not. The cut changes
  how many usable magnitude bins the colour draw has, which
  changes how many numbers it consumes, which moves the
  stream for every draw after it. `current` against
  `larger_diffs` -- same ladder, the cut the only declared
  difference -- shared 1 of 60 fog_only trials, 1 of 30
  together and 0 of 30 conflict.

  Two things were wrong with that. The fog condition could
  not be read as a control, because its detection moved
  between versions for no design reason. And colour
  information leaked in from types the cut never touches:
  `both` gained 16.4 units of summed squared colour
  predictor from its `together` trials alone, about a sixth
  of its total gain over `current`.

  Each draw now has its own generator, seeded from (seed,
  draw name). What that buys is checked here and nowhere
  else, so this verdict matters:

0b. TWENTY DRAWS PER VERSION
----------------------------------------------------------------------
  A version can look better because it is a better design
  or because it drew well: 180 trials out of a pool of
  thousands is one sample. Each version is therefore built
  at 20 seeds. The first, 42, is the
  shipping list -- it gets the figure, report and package.
  The rest are replicates under seeds/, read by step 6,
  which reports each version's mean detection with the
  spread of its own draws beside it.

  THE SHIPPING SEED IS FIXED IN ADVANCE and is not chosen
  on any result. Picking the seed that simulates best would
  be choosing the draw that flatters the design.

0. REPRODUCTION OF THE SHIPPED TRIAL LIST
----------------------------------------------------------------------
  The four design versions deliberately do NOT reproduce
  it: the balance normalisation changed in step 4, so a
  different set of conflict pairs is eligible. The control
  version isolates that -- it reads the legacy pair table
  and uses the legacy rank bins, so if it matches, the
  conflict trials that differ elsewhere differ for that
  reason and the sampler has not drifted.

  The verdict is on the FOUR ANALYSED TYPES. practice,
  catch and consistency are expected to differ: practice
  is now drawn from a mix of types rather than `together`
  alone, and that shifts the random stream for the draws
  that follow it. None of the three is analysed.

  The control also has the earlier run's POOL ORDER
  restored. The pair set was already identical, but the
  shipped list was drawn from a table in a different row
  order, and that order was never reproducible -- step 3
  measured scenes with imap_unordered, so its manifest
  followed worker completion order. Steps 3, 4 and 5 each
  impose a canonical order now, and two runs of step 5
  give byte-identical trial lists; but the shipped list
  itself can only be matched by feeding the old order
  back, which is what REPRODUCE_POOL_ORDER does.

2. WHAT STEP 6 DECIDES
----------------------------------------------------------------------
  The cut is not chosen here. Step 6 simulates each
  version and measures how much better a colour-following
  participant is detected, against how much of the
  dose-response range was given up to get it. The
  sensitivity versions exist so that trade can be read off
  a curve rather than guessed from one value.

  Per-version detail is in each version's own
  trials_report.txt; trial counts per bin and type for
  every version are in bins_by_version.csv; the per-seed
  draws are in seeds_by_version.csv and under seeds/.
